Product — 何を作るか

ゴールは完成ではない。
動くコンセプトを提示すること。

卒業制作では、これまでの学習課題を融合させ、"実際にホストやゲストが登録できるMVP"を作る。目的は、TriArkの世界観を視覚的・動的に、分かりやすく魅力的に伝えること。

ACCOUNT

登録・認証

ゲスト／ホストの役割を分けた会員登録。

LISTING

リスティング作成

活動エリア・体験内容・車両を登録。まず自分がホストとして登録し、必要項目を実体験で検証する。

CHAT

予約チャット

リアルタイムのメッセージ、予約ステータス（問い合わせ→承認→確定）、既読、連絡先の段階的保護。

SAFETY

安全判断の支援

活動エリアの天気と気象庁の警報・注意報を自動表示し、催行可否の判断材料を示す。

将来構想として、AIによるリスティング／プロフィール文の作成支援、"必要に応じて翻訳"する多言語コミュニケーションも見据える。

How to Use — ① どんなプロダクトか

乗り物を持つ人の旅に、
あとから乗せてもらう。

TriArk は、キャンピングカーや船を持つホストが、自分の旅や活動にゲストを同乗させるための場所。 宿のように部屋を貸すのではなく、ホストの時間と行き先そのものが体験になる。

ゲストは「どこへ行くか」ではなく「誰と行くか」で選ぶ。 ホストは、自分の好きな場所と好きなことを、そのまま体験として出せる。 在庫が部屋ではなく人と時間である点が、既存の旅のサービスと決定的に違う。

How to Use — ② どう使うのか

ゲストは探して、
ホストは連れていく。

GUEST
  1. 体験をさがす陸・海・空で絞り込む。ホストを「好きなこと」から探すこともできる
  2. 体験を開く写真、ホストの紹介、開催日程、出発地と目的地までの経路を見る
  3. 日程を選んで問い合わせる空いている日から選ぶ
  4. ホストと話す予約ごとのチャット。同じ画面に、その土地の天気と気象庁の警報・注意報が出る
  5. 確定ホストが承認すると予約が決まる
HOST
  1. 登録して、プロフィールを書く自己紹介、話せる言語とその程度、好きなこと
  2. 「ホストになる」紹介文、活動エリア、Ark（自分の乗り物）の写真、これまでの旅の写真
  3. 資格を申告する海は事業登録・操縦免許・保険が揃うまで公開できない。陸は業務使用の保険を確認する
  4. 体験をつくる出発地、経路、やること、含まれるもの、持ち物、料金、定員、開催日程、送迎の有無
  5. 下書きで保存し、整ったら公開する公開に足りない項目は、その場で示される
  6. 問い合わせに応えるチャットで話し、承認する
How to Use — ③ どんな機能があるか

いま、動いているもの。

  • 登録・ログイン　ひとつのアカウントで、ゲストとホストを兼ねる
  • プロフィール　自己紹介／話せる言語とその程度／好きなこと／写真
  • ホスト登録　紹介文・活動エリア・Ark の写真・旅の写真
  • 資格と保険の申告　海は事業登録・特定操縦免許・船客傷害保険が揃うまで公開できない
  • 体験の作成　出発地の住所と地図、経路、やること、料金、定員、開催日程、送迎の有無、写真
  • さがす　体験は陸・海・空で、ホストは「好きなこと」で絞り込む
  • 予約　問い合わせ → 承認 → 確定
  • チャット　予約ごとの会話。既読が分かる
  • 天気と警報　体験地の天気と、気象庁の警報・注意報を自動で表示
  • 日本語と英語　書いた言語から、相手の言語へ自動で翻訳

Tech — どう作るか

技術は目的ではなく、
手段である。

  • フロントエンド　HTML / CSS / JavaScript、React（学習中）
  • インフラ　Firebase（認証・リアルタイムDB・画像保管）
  • 外部API　天気・気象庁の警報・注意報（出典明記・規約順守のうえ利用）
  • 管理・公開　Git / GitHub

技術構成の詳細は、これから作りながら固めていく段階にある。「完璧な仕様を今示すこと」より「何を作りたいかが明確であること」を重視し、実装は自走しながら判断・改善していく。

Roadmap — 10月7日、そしてその先へ

MVPは、通過点。

PHASE 1

課題をMVPへ統合

認証・チャット・予約フロー・API連携をTriArk MVPとして統合。自分自身をホストとして登録し、リスティング項目を実体験で検証。

PHASE 2

UI/UXのブラッシュアップ

コンセプトが直感的に伝わる動的な見せ方と、ブランド世界観の統一。

PHASE 3 — 〜10/7

デモに仕上げる

通しで動くデモに仕上げ、MVPで「動くコンセプト」を提示する。

KEY FACTORS FOR SUCCESS
  • 法規制モビリティによる有償運送、旅館業法・住宅宿泊事業法、越境時の各国法規制。
  • 競合分析・差別化既存サービスが規模化の中で失った"人と人のつながり"を、TriArkは"ホスト同乗"という構造で取り戻す。TriArkは"ホストが同乗しなければ成り立たない"構造ゆえに、無人運営を許さない。だからこそ、既存サービスが規模化の中で標準化・画一化してきたのとは異なり、一人ひとりのホストの個性と物語が生き、模倣もされにくい。この構造的な独自性を、差別化の核として検証する。
  • ブランド戦略収益の柱となる高付加価値路線を軸に、ブランドイメージを最初から確立する。
  • 規制対応戦略特定地域から小さく始め、try & error で育てる。
